# نصب سامانه بازرسی گروه پرس روی Vercel

این پوشه همان برنامه‌ی سایت است، آماده برای اجرا روی **Vercel**. تنها چیزی که علاوه بر Vercel لازم دارید یک **دیتابیس Turso** است (پایگاه‌داده رایگان و سازگار با کد فعلی). بقیه‌ی چیزها داخل همین پوشه است.

---

## فایل‌های این بسته

| فایل | کار |
|---|---|
| `public/index.html` | کل رابط کاربری (داشبورد، بازرسی، آموزش‌ها، QR و…) |
| `api/[...route].js` | ورودی Vercel؛ درخواست‌های `/api/...` را به برنامه می‌دهد |
| `api/_lib/worker.js` | منطق سرور برنامه (ورود، بازرسی، کاربران، آموزش‌ها) |
| `api/_lib/d1-libsql.js` | اتصال دیتابیس Turso با همان API کلادفلر |
| `vercel.json` | تنظیمات خروجی و پوشه‌ها |
| `package.json` | وابستگی‌ها (فقط `@libsql/client`) |
| `.env.example` | نمونه‌ی دو متغیر محیطی لازم |

---

## مرحله ۱ — ساختن دیتابیس (۵ دقیقه)

1. به `https://turso.tech` بروید و با گوگل یا گیت‌هاب ثبت‌نام کنید (رایگان).
2. دکمه‌ی **Create Database** را بزنید؛ یک نام مثل `pers` و نزدیک‌ترین منطقه (مثلاً Frankfurt) را انتخاب کنید.
3. در صفحه‌ی دیتابیس، **Database URL** را کپی کنید؛ چیزی شبیه `libsql://pers-xxxx.turso.io`.
4. روی **Create Token** بزنید و توکن ساخته‌شده را کپی کنید (فقط یک بار نشان داده می‌شود).

این دو مقدار را جایی نگه دارید؛ در مرحله ۳ لازم می‌شوند.

> راه جایگزین برای برنامه‌نویس‌ها: `turso db create pers` و بعد `turso db show pers --url` و `turso db tokens create pers`.

---

## مرحله ۲ — آپلود روی Vercel

1. به `https://vercel.com/new` بروید و وارد شوید.
2. ساده‌ترین راه: پوشه‌ی `vercel` (همین پوشه) را با ماوس داخل کادر آپلود رها کنید. اگر با گیت‌هاب کار می‌کنید، همین پوشه را در یک ریپازیتوری بگذارید و **Import** کنید.
3. تنظیمات پروژه:
   - **Framework Preset**: `Other`
   - **Root Directory**: همان پوشه‌ای که `package.json` و `api` در آن است
   - **Build Command**: خالی بگذارید
   - **Output Directory**: `public`
4. روی **Deploy** بزنید (قبل از زدن دکمه، بخش مرحله ۳ را هم انجام دهید).

---

## مرحله ۳ — متغیرهای محیطی (اجباری)

در Vercel → پروژه → **Settings** → **Environment Variables** دو مورد را اضافه کنید (برای هر سه محیط Production / Preview / Development):

| نام | مقدار |
|---|---|
| `TURSO_DATABASE_URL` | همان `libsql://...` مرحله ۱ |
| `TURSO_AUTH_TOKEN` | همان توکن مرحله ۱ |

بعد از ذخیره، یک بار **Redeploy** کنید تا مقدارها اعمال شوند.

اگر این دو تنظیم نشوند، سایت بالا می‌آید ولی هر تماس با سرور خطای ۵۰۰ می‌دهد.

---

## مرحله ۴ — اولین اجرا

1. آدرس سایت Vercel را باز کنید. صفحه‌ی **«اتصال سامانه به گوگل‌شیت»** می‌آید.
2. آدرس Web App اسکریپت شیت (`.../exec`) و همان `TOKEN` داخل `apps-script-sheets.gs` را وارد کنید و ذخیره بزنید.
3. با کد پرسنلی و رمز مدیر (همان که در برگه «کاربران» شیت دارید) وارد شوید.

از این به بعد همه چیز مثل نسخه‌ی قبلی است: بازرسی‌ها در گوگل‌شیت آرشیو می‌شوند، کاربران و سوالات از شیت خوانده می‌شوند، و داده‌های عملیاتی (تنظیمات، حضور کاربران، پشتیبان بازرسی‌ها) در دیتابیس Turso می‌مانند.

**مهم:** اسکریپت گوگل‌شیت باید نسخه‌ی تازه باشد (شامل اکشن‌های مدیریت کاربر). Deploy → Manage deployments → Edit → Version: **New version** → Deploy.

---

## اجرای آزمایشی روی کامپیوتر خودتان (اختیاری)

```bash
cd vercel
npm install
TURSO_DATABASE_URL=file:./local.db npx vercel dev
```

با `file:./local.db` یک دیتابیس روی دیسک خودتان ساخته می‌شود و به Turso نیازی نیست.

## عیب‌یابی سریع

| نشانه | علت و راه‌حل |
|---|---|
| خطای ۵۰۰ در همه‌ی درخواست‌ها | `TURSO_DATABASE_URL` تنظیم نشده یا بعد از تنظیم Redeploy نکرده‌اید |
| «رمز اتصال نامعتبر است» هنگام اتصال شیت | `TOKEN` اسکریپت شیت با آنچه وارد کرده‌اید یکی نیست |
| «کاربری با این رمز پیدا نشد» | برگه «کاربران» شیت خالی است؛ اول با اسکریپت، برگه‌ها و کاربران را بسازید |
| تغییرات اعمال نمی‌شود | کش مرورگر؛ یک بار `Ctrl+F5` |

## نکات نگه‌داری داده

- داده‌های این نسخه در **Turso** ذخیره می‌شوند؛ اگر دیتابیس را حذف کنید، تنظیمات و سابقه‌ی داخلی از بین می‌رود (آرشیو بازرسی‌ها در گوگل‌شیت باقی می‌ماند).
- از دیتابیس Turso می‌توانید در پنل خودشان بکاپ بگیرید.
- هیچ رمز یا توکنی داخل این فایل‌ها نیست؛ همه در Environment Variables می‌مانند.
